# Telegram 底部菜单（2026-10-16 更新）

默认交互已改为 ReplyKeyboardMarkup：输入框下方常驻中文键盘，resize_keyboard=true、is_persistent=true、one_time_keyboard=false。发送 /menu 或 /start 展开。

- 节点、主机、订阅：点击中文菜单 → 点击名称 → 选择常用操作，不要求手填 UUID 或 JSON。
- 检测报表：IP纯净度、解锁、收益、被墙检测，中文摘要，最多12项/2400字；不发送供应商原始数据、ASN调试字段或整段JSON。
- 修改操作仍有两分钟单次确认，确认显示目标名称和操作。保留面板原有权限、限流、审计。
- 旧消息中的接口按钮不再进入接口表单，而是提示回到新底部菜单；高级 /api 入口保留但不再是日常菜单，回执同样为中文摘要。
- 复杂配置、实时终端和文件传输仍可在网页工作台处理。

# Telegram 控制菜单（2026-10-16）

- 发送 `/menu`：节点、主机、订阅、3X-UI、任务/巡检、告警、检测/收益报表、系统设置八类菜单。分类分页显示，管理接口从实际 authenticated 路由自动登记。
- 点操作后，带 `{id}` / `{uid}` 的路径先输入参数 JSON；再输入请求体 JSON。GET/DELETE 不需要请求体时自动进入执行/确认。可用 `/api GET /api/nodes`、`/servers`、`/subscriptions` 查真实 ID。
- `/api METHOD /api/路径 {JSON}` 是同一入口的快捷命令，非白名单路由不能调用，不支持外部 URL。GET `/nodes/{id}/api`、探测等历史副作用接口也先确认。
- 所有写操作先显示请求预览，确认票据绑定私聊/发送人/当前管理员，2 分钟有效、原子单次消费；取消、过期、重启和重复点击不执行。不自动重试可能已在节点生效的写请求。
- 身份：仅 `telegram_chat_id` 指定的正数私聊 ID 本人可控制；群组仍只读。复用现存管理员账号和当前 token_version 校验，不创建新管理员、不暴露内部会话。每次执行继续走面板权限、逐台主机授权、写限流与业务审计，另记 `telegram_control` 入口审计。
- 机器人启动时注册 9 条命令和 Telegram 原生命令菜单；设置页「发送测试消息」在私聊同时发送控制菜单。
- 常见密码/token/secret字段在 JSON 回执与确认预览中隐藏；HTTP 207 按部分成功显示，超长结果分页并明确截取。
- WebSocket 实时终端、二进制文件上传/下载、浏览器专用交互仍使用网页工作台；机器人不声称替代这些交互协议。JSON 管理操作可直接在 Telegram 调用。

例：
```
/api GET /api/nodes
/api POST /api/nodes/真实节点ID/users/真实用户ID/renew {"extend_days":30}
```
第二条必须点击一次「确认执行」后才下发。不要使用真实付费用户做测试。
