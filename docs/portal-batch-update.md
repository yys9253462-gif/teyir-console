# 批量更新门户

入口：HY2 节点 → 批量更新门户 → 选择节点 → 一键下发更新。

- 每批最多 20 个节点；全局同时只运行一个批次。
- 需提前配置环境变量 `HY2_INSTALLER_REPO`（格式 `owner/repo`）指定节点门户更新来源仓库；未配置时接口会拒绝执行，避免请求无效上游。
- 节点必须绑定完整的门户管理账号密码；缺失时保留禁用项与原因。
- 服务端逐台执行两轮：第一轮升级门户更新器，第二轮更新前后端及四个计量模块。
- 批次开始时固定 GitHub main 上六个文件的完整 git blob SHA；只有节点回报的全部指纹一致才判文件核验完成。
- 计量运行时仍是旧版视为失败；计量未初始化或存在采集/历史缺口单独标为告警，不混成成功。
- 页面关闭不影响执行；重新打开读取持久化进度。控制台进程重启则任务标记中断，不自动重放写操作。
- 更新请求断连不盲目重发；显示该节点失败，继续其他节点，操作者可再次选择失败节点。
- 只更新门户和计量模块，不升级 Hysteria 内核、不重装节点、不修改用户密码。

API：

- `POST /api/portal-update-batches`：`{"node_ids":["UUID"]}`；需要登录管理会话及 `X-Confirm-Dangerous: yes`。返回 202 仅表示创建任务。
- `GET /api/portal-update-batches/{id}`：读取任务；`latest` 读取最近任务。操作者仅能查看自己的任务，管理员可以查看所有任务。

部署时先应用 `029_portal_update_batches.sql`，再更新 API/Web。节点门户的 `check-version` 需支持 `portal_bundle`，首次更新会自动带入此能力。

测试：Go 批量更新状态机、指纹缺失/不匹配、旧运行时、计量告警、取消等待；前端真实浏览器验证选择、确认、后台进度、重新打开及手机布局。
